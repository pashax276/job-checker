# EDD work-search reports — design

Date: 2026-10-12. Target release: v1.12.0.

## Problem

Jobs are reported to California EDD as work-search contacts on each
unemployment certification. Nothing in the tracker records which jobs were
already reported, or at which stage, so the only way to avoid reporting one
twice (or missing one) is memory.

## Behaviour

A job holds zero or more EDD reports, at most one per stage. Each report says
"this job was reported to EDD at stage X on date Y". The same job can be
reported again at a later stage (Applied, then HM Interview).

Reportable stages are `SCHEDULABLE_STAGES`: Applied, Screen, Assessment,
HM Interview, Panel, Offer. Evaluating, Skipped and Rejected are not
work-search contacts and cannot be reported.

Marking a stage that is already reported moves its date rather than adding a
second row.

## Data

New table `edd_reports`:

| column        | type | notes                                   |
|---------------|------|-----------------------------------------|
| `id`          | text | primary key, uuid                       |
| `job_id`      | text | FK `jobs.id`, cascade delete            |
| `stage`       | text | one of `SCHEDULABLE_STAGES`             |
| `reported_on` | text | `YYYY-MM-DD`, the day it went on EDD    |
| `created_at`  | text | ISO datetime the mark was made          |

Unique on `(job_id, stage)`. Migration `0010` generated by drizzle-kit.

## Server

`src/server/edd.ts`:

- `listEddReports(db, jobId)` — ordered by `reportedOn`, then `createdAt`.
- `setEddReport(db, jobId, { stage, reportedOn }, now)` — upsert on
  `(jobId, stage)`.
- `clearEddReport(db, jobId, stage)` — returns whether a row was removed.
- `listEddStagesByJob(db)` — `Record<jobId, stage[]>` for the list views, one
  query for all jobs.

`getJob` adds `eddReports` to the detail. `GET /api/jobs` rows gain
`eddStages: string[]`; `listJobs` itself is unchanged so export and import
keep their shape.

## API

`/api/jobs/[id]/edd`, mirroring the schedule route:

- `PUT { stage, reportedOn }` — 200 with the report. 404 unknown job, 400 on a
  bad stage or a date that is not `YYYY-MM-DD`.
- `DELETE ?stage=…` — 200 `{ cleared: stage }`, 404 when nothing was marked.

Both wrapped in `withRouteErrors` so a failed write reports its reason.

## UI

**Drawer.** New "EDD" section in the right column, above Timeline, in its own
file `src/components/edd-section.tsx` (`job-drawer.tsx` is already 852 lines).
One chip per reportable stage: reported chips are filled, carry the date and
have a remove button. Below, a stage select (defaults to the job's current
status when reportable, otherwise the first unreported stage), a date input
(defaults to today, editable for backfill) and a "Mark reported" button.

**Timeline.** A third row kind, `edd`: stamp, landmark icon, "Reported to EDD",
stage badge. Timestamped by `reportedOn` so backfilled reports land on the day
they were filed. The merge moves out of the component into a pure
`buildTimeline` in `src/lib/timeline.ts` so the ordering is unit-tested.

**Board and table.** An "EDD" badge on a job whose current status is already
reported, so unreported jobs can be spotted without opening each drawer.

## Backups

JSON export adds `eddReports: { stage, reportedOn, createdAt }[]` per job.
Import parses it into `JobExtras` and restore upserts on `(jobId, stage)`.
The import summary counts what was restored and any malformed entries that
were skipped. A backup without the field leaves existing reports untouched.
xlsx and csv keep the fixed 11-column layout.

## Out of scope

- Board filter for "not reported to EDD yet".
- A weekly view of what was reported in a certification week.
- A marker on the Journey rail.
